# 전역 작업 규칙 (모든 프로젝트 공통)

사용자가 반복해서 지적한 규칙이다. 프로젝트와 무관하게 항상 지킨다.

## 소통
- **사고·계획·응답·플랜 파일 전부 한국어.** 코드 식별자·경로·기술용어만 원문 유지.
- 빌드·테스트·검증 여부는 사실대로 보고. 안 돌렸으면 안 돌렸다고 말한다.

## 조사
- **서브에이전트(Agent/Explore/Plan) 사용 금지.** 직접 Grep/Glob/Read로 조사. (토큰 과다 소모)
- **"확인해봐" = 되묻지 말고 직접 전수 조사** → `파일:라인` + 증상 목록으로 보고. 질문은 조사로 못 가르는 진짜 갈림길일 때만 최소로.
- **추측 금지.** 값·형식·프로토콜·과거 의도 등을 "아마 ~일 것"으로 채우지 않는다. 소스(수신측 파서·스펙·기존 구현)와 대조하거나 사용자에게 확인. 모르면 모른다고 말한다.
- **가설은 결론처럼 단정하지 않는다.** 알려진 사실 전부에 스스로 반증테스트 → 반증조건과 함께 제시. 가설 집합을 가르는 판별 검사를 맨 앞에. 증거가 가르기 전엔 수정·설정변경 금지.
- **"확정" 전 전수 매핑.** 코드 엔티티 전체 집합 열거 → 1:1 매핑 → 안 붙는 것만 후보 → 대안해석(정상일 가능성) 반증 → 근거(파일·줄) 노출. 버그 조사도 동일.

## 수정
- **구현 착수 전 요구사항을 체크리스트로 제시하고 승인받는다.** 완료 후 같은 체크리스트로 재대조해서 보고.
  - 상시 점검: read↔write 대칭 / enum·코드값 정수값까지 일치 / 입력부·표시부 분리 / 선택형처럼 빠뜨리기 쉬운 항목
- **지시 범위 밖 변경 금지.** 개선점이 보이면 고치지 말고 먼저 묻는다. ("꼭 필요해서" 합리화 금지)
- **검증된 코드·명확한 지시는 그대로 구현.** 내 판단으로 덮어쓰지 않는다. 실패 시 전체 재작성 말고 기준선으로 돌아가 하나씩.
- Bash/PowerShell(sed·perl 등)로 파일을 고치는 것도 '수정'에 포함.
- **주석은 요점 한 줄.** 장황한 다줄 블록 금지, 자명한 코드엔 생략.
- **플랜 파일은 전체 재작성 금지.** 추가분만 하단에 덧붙인다.
